# CH03 RAG 知识库 实施计划

> **For agentic workers:** 本计划在主工作区直接执行，不建 worktree。单章连续执行模式：TDD RED→GREEN 逐步推进，仅遇「重要问题 / 难回退选型 / 需用户外部资源」停下。dev-notes/ch03.md 随阶段追加。
> **Spec:** `docs/superpowers/specs/2026-10-16-ch03-rag-design.md`
> **唯一卡点：D2 BGE-M3 接入路线（本地 / API）需用户拍板后才装嵌入依赖**；T1/T2/T3 与 D2 无关，先行。

**Goal:** 交付：① Milvus(Docker) + 两张新表（knowledge_chunks/qa_extraction_staging）；② 结构感知 Markdown 切分引擎；③ BGE-M3 嵌入适配器（接口定死，实现可换）；④ 双写建库流水线（MySQL 权威 + Milvus，幂等可重跑）；⑤ 对话挖知识定时任务（staging + 去重入库）；⑥ query_faq 内部换向量 Top-K（契约不变）+ LIKE 降级。

**Architecture:** 新增 `app/rag/`（chunker/embeddings/vectorstore/indexer/miner/retriever）；`scripts/`（build_knowledge.py 建库、mine_qa.py 挖知识、seed_knowledge.py 种子文档）；`app/core/tools/business_tools.py` 的 query_faq 内部改调 retriever。

**Tech Stack:** Python 3.13 + FastAPI + SQLAlchemy 2.0 Async + pymilvus + sentence-transformers/API（D2 待定）+ pytest

## Global Constraints

- DDL 与 `各章建表.md` ch03 节逐字一致落 `scripts/sql/ch03_schema.sql`；`apply_schema.py` 增量执行（复用 `--if-not-exists`）。ORM 与 DDL 一一对应；自增主键沿用 `BigInt`（通用 BigInteger + sqlite 回落，CH02 翻车结论：勿加 unsigned）。
- Milvus 集合 `knowledge`：主键 `chunk_id`（Int64，与 MySQL knowledge_chunks.id 对齐）、向量 `embedding`（FloatVector，**1024 维**，BGE-M3 定死）、标量 `category`（VARCHAR，检索后过滤/展示用）；`ensure_collection` 幂等；insert 走 upsert 语义。
- 双写状态机：MySQL pending → embed → Milvus upsert → 回填 `vector_id` + `vectorize_status=done`；重跑只捞 pending；回填与插入必须同 task 内完成，中途失败留下 pending 可重捡（验收标准 2）。
- 切分引擎零新依赖纯函数：`split_document(markdown: str, config: ChunkConfig) -> list[Chunk]`；目标块长可配（默认 400 字）；重叠 ~15% 且裁到最近句号；表格按行切复制表头。
- 嵌入适配器接口：`embed_texts(texts: list[str]) -> list[list[float]]`（1024 维）；本地实现（sentence-transformers BGE-M3）与 API 实现（OpenAI 兼容 /embeddings）二选一由 D2 定，`.env` 配置化；测试用 `FakeEmbedder`（确定性 1024 维）。
- query_faq 契约不动：入参 `keyword: str`，出参文本格式与 CH02 一致（命中列表 / 「未找到」文案）；内部 = embed(keyword) → Milvus search(top_k=5) → 回 MySQL 取原文 → 格式化；Milvus 异常 → 降级 LIKE（CH02 原实现），日志告警不中断聊天。
- 挖知识：`batch_no` 分批（默认 20 会话/批）；LLM 抽 QA 写 staging（extracted）→ 规范化去重（question 去空白/标点后，与 staging 内 + knowledge_chunks 现有 questions 比对）→ kept 入 knowledge_chunks（content_type=qa_mined, category=来源分类）→ discarded；CLI 可重复执行。
- 种子知识文档 AI 合成（注明），故意覆盖切分分支：多级标题、超长章节、大表格、关键条款段落。
- 密钥只进 `.env`；Milvus 连接 `MILVUS_URI`（默认 `http://127.0.0.1:19530`）走 `.env`。
- pymilvus / sentence-transformers API 用法以 Context7 查证为准（记录进 dev-notes）。

## Review Focus

1. 双写一致性：中断重跑后不得有重复向量（Milvus 主键对齐）或永久 pending 行。
2. 切分边界：重叠块不得半截话（句号裁切）；表格块必带表头；标题路径继承正确。
3. 去重口径：规范化后与知识库现有 questions 去重，同义不同写法是否漏放（本章只做规范化精确/包含去重，语义去重留 CH04）。
4. query_faq 契约与降级：CH02 回归全过（徽章/回灌格式不变）；Milvus 挂了走 LIKE 不抛异常。
5. 幂等键：chunk id ↔ Milvus 主键严格对齐；upsert 重复不报错。
6. 资源：Milvus 三容器 + MySQL 共存内存观察（15.6G 上限）。
