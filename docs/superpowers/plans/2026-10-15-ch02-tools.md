# CH02 Function Calling 工具链 实施计划

> **For agentic workers:** 本计划在主工作区直接执行，不建 worktree。单章连续执行模式：TDD RED→GREEN 逐步推进，仅遇「重要问题 / 难回退选型 / 需用户外部资源」停下。dev-notes/ch02.md 随阶段追加。
> **Spec:** `docs/superpowers/specs/2026-10-15-ch02-tools-design.md`

**Goal:** 交付：① FastAPI + SQLAlchemy(Async) 分层骨架 + Docker MySQL 四张表；② 五个 @tool 业务工具 + 注册中心（Schema 校验 / 错误分诊 / 超时重试）；③ 单轮工具调用接入 SSE 流式聊天（状态帧 + 全量落库 + 工具徽章）；④ 原生 HTML 聊天页。

**Architecture:** `api/routes` → `services` → `repositories` → `models`；`core/tools/` 注册中心 + 五工具；`core/llm.py` 扩 bind_tools 工厂；SSE 事件扩 tool_start/tool_end。单轮收敛：bind_tools invoke → tool_calls 则执行回灌 → astream 终答（二次仍要工具 → 兜底摘要，不循环）。

**Tech Stack:** Python 3.13 + FastAPI + SQLAlchemy 2.0 Async（aiomysql 生产 / aiosqlite 测试）+ LangChain @tool + pytest

## Global Constraints

- `DATABASE_URL` 走 `.env`，默认 `mysql+aiomysql://root:root@127.0.0.1:3307/kefu_agent`；`DB_ECHO` 开关 SQL 日志。代码零硬编码连接串。
- docker-compose.yml：mysql:8，端口 `3307:3306`，库名 kefu_agent，root 密码走 `.env` 的 `MYSQL_ROOT_PASSWORD`（compose 变量替换）；healthcheck 就绪判定。
- DDL 与 `各章建表.md` ch02 节逐字一致落 `scripts/sql/ch02_schema.sql`；ORM 字段与 DDL 一一对应，ENUM 用 SQLAlchemy `Enum`。
- 单轮工具调用：`llm.bind_tools(TOOLS).invoke(msgs)` → tool_calls 非空 → 状态帧 + 执行 + `ToolMessage(tool_call_id=...)` 回灌 → `llm.bind_tools(TOOLS).astream(msgs)`；二次 tool_calls → 兜底摘要直出，不执行。
- 工具执行：注册中心按 `tool.name` 调度；执行前 pydantic 校验（`args_schema`）；超时 `asyncio.wait_for`（默认 10s，可配）；仅网络类异常重试一次；错误分诊三类（参数不合法 / 查询落空 / 真故障）全部回灌为 ToolMessage content。
- mock 三工具：`random.Random(f"seed:{order_id}")` 确定性生成；不建表不接外部。
- query_faq：参数化 `LIKE`，`%`/`_`/`\` 转义；无命中返回固定文案（供 LLM 组织「没查到」）。
- create_ticket：工单号 `T{yyyyMMdd}{4位序列}`，序列 = 当日 max+1（`SELECT MAX` 在事务内，防并发撞号先以注释标注，CH08 前不建唯一约束竞争测试）。
- SSE 事件协议：`tool_start {"tool_call_id","name","args"}` → `token {"content"}` → `tool_end {"tool_call_id","name","ok","summary"}` → `done {"session_id","finish_reason"}`；`error` 不变。事件顺序：tool_start 必早于对应 tool_end。
- 落库：每轮 user 消息、assistant 消息（含 tool_calls JSON）、tool 消息（content=结果摘要，tool_call_id）全量落 messages；conversations 首轮静默新建。
- 测试：单测 SQLite（`sqlite+aiosqlite:///:memory:`，`Base.metadata.create_all`）；eval ≥90%；集成验收真 MySQL + 真 GLM。
- 密钥只进 `.env`；`.env` / `__pycache__` / `.pytest_cache` 不提交。
- LangChain / SQLAlchemy / FastAPI API 用法以 Context7 查证为准（记录进 dev-notes）；新增依赖（aiomysql/aiosqlite）装后汇报。

## Review Focus

1. 未知 conversation_id → 静默新建空会话（延续 CH01）。
2. 历史重建：assistant(tool_calls) 与 tool(tool_call_id) 两条消息按序对号，回灌 LLM 不出现孤立 tool 消息。
3. create_ticket 工单号当日唯一且格式 `T20260701008` 式。
4. LIKE 转义：keyword 含 `%`/`_` 不引发全表误匹配。
5. mock 确定性：同 order_id 两次调用结果逐字一致。
6. SSE 时序：tool_start → token → tool_end 不乱序；工具异常时流不挂起、error 语义正确。
7. SQLite/MySQL 方言差：ENUM 写入、JSON 列读写在双库一致。
