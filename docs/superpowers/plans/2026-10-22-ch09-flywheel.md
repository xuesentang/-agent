# CH09 实施计划：飞轮闭环（无 Langfuse 版）

> spec：`docs/superpowers/specs/2026-10-22-ch09-flywheel-design.md`（D1-D12）
> 每完成一个任务：跑测试 → 追记 `dev-notes/ch09.md` → 本地 commit。

## T1 表与数据层（review_queue / eval_runs / intent_usage / 池表加列）

- `app/models/review_queue.py`、`eval_run.py`、`intent_usage.py`；`low_confidence_question` 加
  `retrieved_chunks`(JSON) + `matched_review_id`(FK)。
- `app/repositories/{review_repo,eval_run_repo,usage_repo}.py`；`low_confidence_repo` 加
  `list_unmerged`、`set_matched_review`、`list_by_review`。
- `scripts/sql/ch09_schema.sql`（照 `各章建表.md` 605-640 + intent_usage 的 DDL，自写）。
- 测试：`tests/test_flywheel_repo.py` —— 累加次数不新建行、状态流转、池表新列读写、
  `list_unmerged` 只挑未归并的、按 review 列原话。

## T2 三入口统一入池 + 快照 + 👎 接后端

- `app/services/flywheel.py::enqueue(...)`（唯一入池入口，含快照裁剪到 top5/120 字）。
- 闸拦下、自评拦下两处改调 `enqueue` 并带 citations。
- `POST /api/v1/feedback`：`{conversation_id, question, rating, citations?}`；
  `rating=down` 才入池（`source=user_feedback`），`up` 只回 ok 不落库。
- 前端 `renderFeedback` 改成调接口，失败静默（反馈不该报错给用户看）。
- 测试：入池快照裁剪、非法 rating、up 不入池、前端抓不到 citations 时快照为 NULL。

## T3 evidence_confidence 正式闸 + 阈值校准

- `app/agent/gate.py`：加 `evidence_confidence(citations, min_score)` 纯函数；`check_gate`
  先用它粗筛（`EVIDENCE_MIN_CONFIDENCE`），再自评。新增原因码 `confidence_low`。
- 配置：`EVIDENCE_MIN_CONFIDENCE`（默认值由 T3 校准后填）、权重三个常量写死在 gate 里并注明。
- `scripts/calibrate_gate.py`：跑 ch04 评估集取真实 citations → 算 confidence →
  正负例扫阈值 → 出 `reports/ch09_gate_calibration.md` + 选定值。
- 测试：公式边界（空引用、单条、分差为负、有效证据数封顶）、reason 码映射、
  闸拦下时不调自评模型（用假模型计数）。

## T4 飞轮流水线（标准化 + 查重 + 入队 + 归并落点）

- `app/services/flywheel.py` 追加：`normalize(question, model)`、`dedupe(candidate, pool, model)`、
  `run_batch(session_factory, ...)`。
- 规则查重：`_rule_match()`（规范化相等 / 互相包含且长度差 ≤ 40%）。
- 模型查重：top-20 待审问题 + 结构化输出 `{matched_id|null}`；失败回落「新建」并记 failed。
- `scripts/run_flywheel.py --batch 50 --dry-run`。
- 测试：规则命中优先（模型不被调用）、模型命中累加次数、未命中新建、失败不吞、
  `matched_review_id` 写回。

## T5 审核通过/驳回 + 写回知识库

- `app/rag/indexer.py` 抽出 `vectorize_pending(session_factory, store, embedder)`，
  `build_index` 改用（行为不变）。
- `approve()` / `reject()`：通过 → 建 chunk（category=飞轮补充）→ 向量化 → 状态置通过；
  驳回 → 只改状态。二次审核更新答案不新增重复块。
- `scripts/review_cli.py approve|reject|list`（无浏览器时的可用路径）。
- 测试：Fake embedder/store 全链路、重复通过不重复插、驳回不写库。

## T6 评估流水线与 eval_runs

- `app/eval/metrics.py`：从 `tests/eval/run_rag_eval.py` 抽出 recall/mrr/加权口径，
  脚本改 import（输出与 `reports/ch04_eval_v2.md` 数值一致）。
- `app/services/eval_service.py::run_round(cases, strategy, triggered_by, with_generation)` → 写 `eval_runs`。
- `scripts/run_eval_round.py`；`main.py` 加可选定时（默认关）。
- 测试：指标抽取后与原实现数值一致、run_round 落表字段、趋势查询顺序。

## T7 后台页 `/admin/review` + 接口

- `app/api/review.py`：`GET /review/queue`、`GET /review/{id}`（含原话 + 快照）、
  `POST /review/{id}/approve`、`POST /review/{id}/reject`、`GET /review/trend`。
- `app/static/admin/review/{index.html,review.js,review.css}`：左列表右详情、核准答案预填、
  通过/驳回、下方评估趋势条形。
- 测试：接口契约、非法 id/状态、未知类目式空返回。

## T8 cost 统计（按意图）

- `app/services/usage_service.py`：`record_turn(intent, route, prompt_tokens, completion_tokens, source)`。
- `agent_chat` 落 `intent_usage`（估算，`token_source="estimated"`），失败只记日志。
- `GET /api/v1/usage/by-intent` + `/admin/review` 页面顶部小卡片（或独立区块）。
- 测试：聚合口径（占比/总量）、估算函数对中文的单调性、表写失败不影响主链路。
