# CH04 评估真实化设计（E0-E6）

日期：2026-10-20
状态：已与用户确认范围（≥350 块 / 15 篇；judge 配置槽位由用户填 .env）

## 0. 为什么要重做

CH04 第一版评估在 21 块的知识库上跑出 R@5=1.00、MRR 0.913，据此下了「hybrid 不重排低于 dense」「重排把 dense 追回来」两个结论。复核后判定这套评估**不具备区分度，结论不可用**：

| 病灶 | 实测 | 后果 |
|---|---|---|
| 库太小 | 21 块，Top-10 占 48%、Top-5 占 24% | 第一阶段≈半库扫描，R@5=1.00 是算术必然 |
| 构造性泄漏 | 库我生成、题照库出、`expected_section` 抄章节名 | 考的是「能不能找到我抄的那节」，不是检索能力 |
| 负例只有 far | 2 条且一眼库外 | 真实拒答错误主要发生在 near（相关但答不了）上，完全没覆盖 |
| 裁判=生成 | 均 glm-5.3-flash | 自评自判，绝对分数不可信 |

本设计只解决这四条，不做多轮、不做真实日志回流（P2）。

## 1. 设计决策

### D1 扩库：15 篇 / ≥350 块 / 3 品类，事实骨架手写、话术交模型

- **为什么不是 AI 全权生成整篇**：陷阱（旧版与现行冲突点、同族型号差异、干扰品类边界）必须跨文档一致，模型自己编会前后矛盾，导致 ground truth 无法标注。所以**型号、数值、版本、冲突点由我写进骨架**（`scripts/kb_blueprint.py`），模型只负责把骨架扩写成啰嗦、带表格、带免责声明的真实文档语气。
- **为什么不能太"标准"**：文档要保留电商原文的毛病——重复表述、跨小节互相引用、旧版残留、口径模糊。润色成 FAQ 标准答案会让 BM25 变得异常好命中，评估又回到「抄写能力」。
- 品类：鞋靴、小家电、户外装备；保留现有 3 篇作为现行主干。
- 分块量：目标 ≥350 块。表格密集的型号/参数/时效表按行切分，是块数的主要来源。

### D2 三类脏数据（这是区分度的来源，不是装饰）

1. **旧版与现行并存**：`legacy_*_2024.md` 与现行政策同时入库，关键数值不同（如无理由期限 7 天 vs 15 天、运费门槛）。检索会捞到旧版，生成若不看版本就会答错——考的是「会不会被旧版骗」。
2. **相邻品类干扰**：宠物用品文档含通用售后条款但没有鞋靴/家电的答案，占 10-20%。考 near 型拒答。
3. **同族多代型号**：W20/W40/W60、LP100/LP200 等，差异只在个别参数。考 B 桶是否被型号 token 带偏到隔壁代。

### D3 召回深度随语料规模下调

`RECALL_LIMIT`（两路各召回条数）50 → 20。500 块量级下 20 条约 4%；50 条等于 10%，又会退回「大范围扫描」。这是配置项，不是硬编码。

### D4 评估集：分桶 + D.far/near + 噪声 + 权重

- 桶：`A_policy`（政策直问）、`B_model`（带型号）、`C_colloquial`（口语/别称）、`E_multi`（一问多事）、`D`（不可答，细分 `subtype: far|near`）。
- **near 的五种构造**（每类至少 2 条）：①库里有这个型号但没写这项功能；②同一小节挖空一个事实后再问；③问尚未生效或已下线的政策（旧版有、现行没有）；④问竞品对比；⑤问知识库明令禁止承诺的内容（到账时间、赔付金额、具体时效）。
- 每行字段：`id / query / bucket / subtype(仅 D) / difficulty / expected_section / expected_keywords / answerable / source / noise / weight / note(构造说明)`。
- **出题与标注分离**：题目由一个模型在「只看得到文档目录与商品页、看不到答案小节」的条件下生成；`expected_section` 与 `expected_keywords` 由我按骨架人工标注。这是对 P1-1 的本地化——不引外部语料（本项目数据策略是 AI 合成），改用「出题者看不到答案」切断泄漏。
- 噪声变体：每个可答题再出一条变体（错别字/型号写法变体/去上下文/情绪前缀），单独 `noise` 字段标注，指标分「干净题」与「噪声题」两列报。

### D5 指标口径

- 检索段：Recall@5 / Recall@10 / MRR，按桶 + 按干净/噪声分组。
- 生成段：Faithfulness（裁判判每条主张是否有证据支撑）；不采用「要点逐字出现在答案里」的覆盖度——那是在考抄写。改用 `expected_keywords` 的**语义覆盖**由裁判判（关键词作为提示给裁判，不要求逐字）。
- **双口径**：同时报算术平均与 `weight` 加权平均，两者都写进报告；权重按「假设的工单频次」设定，并在报告里声明这是假设值（无真实工单）。
- 拒答：`D_far` 与 `D_near` 分开报，并给出被哪条证据骗过的快照。

### D6 裁判与生成分离

- 新增配置 `judge_model` / `judge_base_url` / `judge_api_key`，空则回落生成模型，并在报告 meta 里显式标注「裁判=生成模型，仅可横向比，不可当绝对准确率」。
- `.env` 由用户填写，代码只读不写。

### D7 人工抽检

无第二个人，做**单人抽检**：每桶抽 2-3 条共 12 条，我逐条核对裁判判定，报不一致率与不一致原因。不做 Cohen's κ（单人算不出来，硬算就是假装严谨）。

## 2. 验收标准

1. 库 ≥350 块，Top-10 占全库 ≤3%；
2. 四策略指标不再贴顶：MRR 落在 0.6-0.85 区间，且策略排序**有解释**（不能是「全都差不多」）；
3. `D_far` 拒答率 ≈1.0 且 `D_near` 明显更低——两者都 1.0 说明 near 题出得太容易；
4. 噪声题指标明显低于干净题（否则噪声没起作用）；
5. 加权分与算术平均出现可见差异；
6. 报告能区分生成模型与裁判模型，人工抽检不一致率如实记录；
7. 与 `ch04_cases_baseline.jsonl` / `ch04_retrieval_baseline.md` 逐项对比，写清变化原因。

## 3. 不做

- 多轮对话评估、全链路评估、真实日志回流（P2）；
- 引入外部真实语料（本项目数据策略：AI 合成 + 注明）；
- 第五桶（用 subtype 扩展，避免改桶结构）。
