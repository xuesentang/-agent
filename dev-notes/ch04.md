## 2026-10-20 10:2x-10:5x T5-T6:生成质量控制 + 引用溯源(含前端)

### 我的关键产出

- **证据自评闸**(`app/rag/selfcheck.py`):**生成之前**判「手里这几条证据够不够答这个问题」——答复是流式的,吐出去再判只剩事后道歉。判定失败一律当「够」(fail-open),避免上游抖动把所有正常问题判死。
- **拒答两入口**(`app/services/tool_chat.py`):零命中 → `retrieval_low_conf`;自评判不够 → `self_check`。两者都写 `low_confidence_questions`(原话/来源会话/原因),并直接返回固定拒答话术、不进生成;`done` 事件带 `finish_reason=abstain` 与 `abstain_source`。
- **引用编号**(`app/rag/citations.py`):编号只在 `build_citations` 产生一次,prompt 与前端共用同一份列表;`order_for_prompt` 做首尾放置(1,3,5,4,2),编号不变只调位置——中段是大模型注意力的低谷。
- **引用下发**(SSE `citations` 事件)+ **前端**:答案里的 `[n]` 渲染成可点角标(DOM 拼节点,不用 innerHTML——答案来自模型,塞 HTML 等于自开注入口),点开右侧面板看章节路径 + 原文 + chunk_id;每次回答挂 👍/👎,点一次点亮 + 锁死 + 显示「已反馈」。
- **System Prompt**:加引用规则(编号只能用返回里出现过的)+ 负面知识清单(禁止承诺到账时间/赔付金额/发货时间点)。

## 2026-10-20 10:5x T7:评估体系(带难度梯度与 ground-truth 的分桶用例)

### 用例怎么设计

26 条,`tests/eval/ch04_cases.jsonl`,一条一行 json:`id / query / bucket / difficulty / expected_section / expected_keywords / answerable`。

- **命中判定用 `expected_section` 而不是块 id**:块 id 会随切分参数变,章节路径不会。命中 = 期望章节名是命中块 `section_path` 的子串——这样重跑建库、换切分粒度,ground-truth 都还成立。
- **分桶按「考什么能力」而不是按难度线性排**:
  - `A_policy` 政策直问(退换货/运费/发票)——语义路该赢;
  - `B_model` 带具体型号(如「S23 支持快充吗」)——关键词路该赢,这是 BM25 的存在理由;
  - `C_colloquial` 口语/别称(邮费→运费、保修→质保)——考 Query 理解;
  - `E_multi` 一句话问两件事——考召回是否被单点问题带偏;
  - `U_unanswerable` 2 条知识库里根本没有(货到付款、会员积分兑换)——考拒答。
- 只对 `answerable=true` 的算 Recall/MRR,不可回答的单独走拒答统计。混在一起算会把「拒绝回答」错算成「检索失败」。

### 四策略对比(真栈:真 BGE-M3 + 真 Milvus Lite + 真重排,26 题 / 24 可答)

`python -m tests.eval.run_rag_eval --no-generation`:

| 桶 | n | dense R@5/R@10/MRR | bm25 | hybrid | hybrid_rerank |
|---|---|---|---|---|---|
| A_policy | 6 | 1.00/1.00/1.000 | 1.00/1.00/0.806 | 1.00/1.00/1.000 | 1.00/1.00/1.000 |
| B_model | 6 | 1.00/1.00/1.000 | 1.00/1.00/**1.000** | 1.00/1.00/1.000 | 1.00/1.00/1.000 |
| C_colloquial | 6 | 1.00/1.00/0.694 | 0.50/1.00/0.353 | 0.83/1.00/0.639 | 1.00/1.00/**0.764** |
| E_multi | 6 | 1.00/1.00/0.889 | 0.83/1.00/0.778 | 1.00/1.00/0.889 | 1.00/1.00/0.889 |
| **全部** | 24 | 1.00/1.00/0.896 | 0.83/1.00/0.734 | 0.96/1.00/0.882 | 1.00/1.00/**0.913** |

### 怎么读这组数

1. **重排赢了,但赢在顺序不在召回**:`hybrid_rerank` MRR 0.913 全场最高,R@10 和 dense 一样都是 1.000。它的贡献是把「答案块排第几」往前推,不是「能不能捞到」。这符合 CrossEncoder 的定位——它只看 query-doc 相关性、不参与候选生成。
2. **hybrid(不重排)反而低于纯 dense**(0.882 < 0.896),这个结论我没藏。原因是 RRF 对两路一视同仁:BM25 路在口语桶就是弱路(C_colloquial MRR 0.353),融合时把 dense 的头名摊薄了。**所以「上了混合检索就一定更好」是错的,融合之后必须有重排兜底**——这也是把默认策略定成 `hybrid_rerank` 而不是 `hybrid` 的实测依据。
3. **BM25 的价值在型号**:`B_model` 桶 bm25 MRR 1.000,和 dense 并列第一。这条桶的问题是「S23 快充」这种,字面 token 精确,关键词路不需要任何语义理解就能命中——验收标准 2 就是这么过的。反过来说,`C_colloquial` 桶 BM25 R@5 只有 0.50,口语里既没型号也没专有名词,关键词路天然无从下手。
4. **重排对口语桶收益最大**:C_colloquial MRR 0.639 → 0.764(+0.125),远大于其它桶(基本不动)。因为口语题的候选里往往混着一堆「字面不沾但语义相关」的块,CrossEncoder 才分得开。
5. **拒答 2/2**:两条知识库没有的问题都被判「证据不足」并给出正确理由(证据全是运费/发票/退换货,与货到付款、会员积分无关)。注意这里证据不是 0 条——因为是 top-10 强行取满,所以走的是 `self_check` 入口而不是 `retrieval_low_conf`,这正是把闸做成「自评证据够不够」而不是「有没有命中」的原因:稠密检索几乎不会零命中,永远能给你 10 条似是而非的东西。

### 取舍

- 检索段与生成段分开跑(`--no-generation` / `--generation-only`):重排在 CPU 上一档就要十几分钟,四策略 + 生成挤在一次跑会被工具的 timeout 掐掉,分两次跑的数字完全一致(检索是确定性的)。

## 2026-10-20 11:0x T8:code review

### 修掉的

- **`_category_expr` 原来只删引号就当消毒**。类目名要拼进 Milvus 标量表达式,`category.replace('"', "")` 挡不住运算符注入;虽然目前没有任何调用方传 `category`(能力先建、消费方在后续章节),但它是照着「将来会接工具入参」写的,那时模型就能填这个字段。改成白名单正则(`中文/字母/数字/空格·/、-` 以外一律 `ValueError`),不玩转义——Milvus 表达式没有可靠的引号转义约定。补 1 条单测:`'a" or id > 0 or "'` 必须报「非法类目名」。
- 顺手删掉根目录一个 0 字节的 `新建 文本文档.txt`(昨天 23:34 的记事本残留,无内容)。

### 看过但决定不改的(取舍,写进 README 已知限制)

- **同一轮里既查单又查知识库时,知识库零命中会导致整轮拒答**。`query_faq` 零命中 → `bucket.called=True` 且 `items` 为空 → 闸判 `retrieval_low_conf`,直接返回拒答话术,连同轮查到的订单状态一起丢了。反方向的改法(同轮有别的工具结果就跳过闸)会把「政策类问题」放行给模型凭常识答,而凭常识答出错误政策正是这道闸要拦的东西。**选保守**:宁可少答一次,下一次有人从 `low_confidence_questions` 里看到它。已写进 README 已知限制。
- **自评失败 fail-open**。范本是 fail-closed,理由更硬(见 `能力差异.md` 的对比)。我保留 fail-open 是因为 CH04 还没有转人工出口,自评抖动时全员拒答等于服务停摆;等 CH05 把「转人工 / 建工单」两个按钮做出来,再改成 fail-closed——那时多拒一次的代价只剩多点一下。

### 没问题的关键点(复查确认)

- 编号只在 `build_citations` 产生一次,`format_evidence` 内部套 `order_for_prompt`,prompt 与前端共用同一份列表,不会错位;
- `citations` 事件在终答落库之后、`done` 之前发,前端不会出现「done 到了引用还没到」;
- 拒答路径先落库再吐 token,不是吐完再落库;
- `_run` 的 released 重试只重试一次,失败才抛 `VectorStoreError`(不吞异常,上层 `query_faq` 降级 LIKE)。
