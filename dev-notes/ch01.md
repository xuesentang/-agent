## 2026-10-15 09:2x Brainstorming 阶段

### 用户关键原话（需求原文）

- "我要用 Superpowers 模式做一个电商智能客服系统,第一步先跑通纯对话。"
- 功能需求：① 对话接口支持多轮、SSE 流式逐 token；② PromptTemplate 模板化 + system prompt 写清客服角色与行为约束；③ with_structured_output 把售后描述提取成订单号/诉求类型/期望方案；④ 多轮上下文最简版：历史消息裁剪 + token 预算控制。
- 技术栈："Python + FastAPI + LangChain"，"模型接入直连上游,应用侧统一说 OpenAI 协议,地址、模型名、密钥全在 .env,GPT、Claude、DeepSeek、Ollama 都能换着接，但当前先按照deepseek写入，密钥稍后我自行填入"。
- 本章不做：工具调用、Agent 循环。
- 验收标准：① curl 调对话接口能看到流式回复；② 连续问两轮，第二轮续上第一轮上下文；③ 发一段售后描述，能拿到结构化 JSON。
- 工作要求：全程 Superpowers 流程；不可单测任务用标注样例/评估集验证替代 TDD；Context7 查最新官方文档；技术选型定死，矛盾时停下来问。

**Context7 / 官方文档查证结论**（动手前全部落实）：

| 事项 | 查证结论 | 来源 |
|---|---|---|
| LangChain 流式 | `model.astream()` + `async for`，`chunk.text` 为增量文本 | Context7 /langchain-ai/docs |

| 消息裁剪 | `langchain_core.messages.utils.trim_messages` + `count_tokens_approximately`，参数 strategy="last" / max_tokens / start_on="human" / end_on=("human","tool") | Context7 /langchain-ai/docs |

| DeepSeek Tool Calls | ✓ 支持（对应 `method="function_calling"`） | api-docs.deepseek.com 模型特性表 |

**关键技术风险（写进 spec 的决策点）**：`with_structured_output` 默认 method 是 `json_schema`，但 DeepSeek 官方文档只承诺 `json_object`（→ LangChain 的 `json_mode`）和 Tool Calls（→ `function_calling`）。json_mode 有空 content 风险且 schema 要写进 prompt；function_calling 的 schema 由 tool 定义承载、有 Pydantic 自动校验。倾向 `function_calling`，实现时用标注样例验证，翻车则退 `json_mode`。

### 关键裁定与翻车（详见 SDD ledger）

1. **FastAPI SSE 踩坑（T6 翻车两次）**：① `AsyncGenerator[ServerSentEvent, Any]` 与 `AsyncIterable[ServerSentEvent]` 注解均触发 "Invalid args for response field"——fastapi 0.143.1 把返回注解当 response model，需 `response_model=None`；② 路由函数必须自身为 async generator（yield 转发），`return` 一个生成器会被当协程处理。Context7 文档示例是 yield 形式，与踩坑结论一致。
2. trim_messages 中文计数实测：单条 34/21 token（count_tokens_approximately），原测试预算 30 连一条都装不下→空列表是 allow_partial=False 的正确行为，修测试而非迁就。
3. 环境事实：langchain 1.4.6 / langchain-core 1.6.10 / langchain-openai 1.7.2 / fastapi 0.143.1 / pydantic 2.14.1，与 Context7 查证文档一致。
