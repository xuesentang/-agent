# 设计 Spec · 小智客服前端改版（三方向共同输入）

> 这份 spec 是三个方向初稿的**唯一共同输入**。三个版本各自独立工作、互不参考，
> 只换设计逻辑，内容与 DOM 契约必须一字不差，这样用户才能横向对比。

## 1. 这是什么产品

「小智」是一个**电商智能客服 Agent**，跑在本地：FastAPI + LangGraph，前端就是三个静态页面。
它不是"一个能聊天的搜索框"，它的卖点是**把 Agent 的决策过程摊开给人看**：

- 每轮回答带**引用角标**，点开能看知识库原始条款（来源原文面板）；
- 每次工具调用（查单 / 查物流 / 建工单）在气泡上方留**轨迹徽章**，有 running / ok / fail 三态；
- 气泡上方有一行**决策流**：意图 → 路由 → 检索命中数 / 置信度；置信度低于阈值时干脆**拒答**（虚线气泡）；
- 写操作（建工单、退款）在落库前弹**确认卡**：确认后才提交，取消就什么都不发生；
- 检索不到就绪答案时，问题会进**数据飞轮池**，后台人工核准后回写知识库。

这是求职作品集里的项目页，看的人是**面试官 / 技术同行**，演示时是用户在笔记本上边说边点。

## 2. 目标受众与使用场景

- 主场景：1440×900 笔记本屏，一人演示、一到三人围观（观众距离约 60–80cm，不是手机 10cm，也不是投屏 10m）。
- 次场景：用户自己截图发到简历/文章里，所以**首屏必须经得起截图**。
- 观众不是设计师，是工程师。他们对"漂亮"不敏感，但对**假**极敏感：一眼能看出哪里在装。

## 3. 核心信息（首屏必须一眼看全的四件事）

1. 这是一个**客服对话**（左边能切会话，中间是对话，下面能输入）。
2. 每句回答都**有据可查**（引用角标 + 来源 chip + 可展开的原文面板）。
3. Agent 的**内部动作是可见的**（工具徽章、意图/路由、置信度）。
4. 它有**边界**：不确定就拒答，写操作要人确认。

## 4. 情感基调

工程可信 > 好看。要的是「这台机器在记录，不在表演」：克制、精确、有台账感。
不要：科技蓝紫渐变、发光到糊、玻璃拟态堆叠、"AI 感"粒子和动效。
可以：纸感或机箱感的底色、发丝线、等宽数字/编号、克制的单一信号色。

关键词：台账、仪表、留痕、可信、安静但不空。

## 5. 输出格式与尺寸（三版必须统一）

- **单文件 HTML**（内联 CSS，不引任何外部资源：不许 Google Fonts、不许 CDN、不许图片外链）。
  理由：项目是本机离线演示，掉字体/裂图就是演示事故。
- 字体只能用系统栈：中文 `"PingFang SC","Microsoft YaHei","Noto Sans SC"`；等宽 `ui-monospace,"SF Mono",Consolas,"Cascadia Mono",monospace`；衬线可选 `Georgia,"Songti SC","SimSun",serif`。
- 页面按 **1440×900 视口**设计，`100vh` 满屏三/两栏布局，不出现整页纵向滚动（只有消息区内部滚动）。
- 截图命令（在 `D:\客服agent` 下）：
  `npx playwright screenshot "file:///D:/客服agent/design-demos/<文件名>.html" "design-demos/<文件名>.png" --viewport-size=1440,900`

## 6. 已知约束（硬）

- 禁 emoji 当图标（现在的 `🤖` 头像就是待替换项）。头像用**几何/字母/纯 CSS** 做，或干脆只留文字标识。
- 禁紫→粉渐变、禁彩虹渐变条、禁「圆角卡片 + 左侧彩色竖条」这种偷懒容器。
- 正文 ≥14px，标签/注脚 ≥12px，正文对比度 ≥4.5:1。留白是构图不是内容缺席（首屏要有明确视觉锚点）。
- 交互可以写成纯 CSS 的 hover/active + 少量内联 JS 演示，但**不许出现按钮点了没反应**。
- 不写假数据装饰（假头像墙、假统计数字）。所有数字都来自下面第 8 节的真实内容。

## 7. DOM 契约（三版都必须用这套 class 名，允许另加自己的类）

未来要把这套 CSS 落回 `app/static/style.css`，而消息流是 `chat.js` 动态生成的，class 名写死在那里。
所以初稿必须按这套结构渲染（内部可以再包你的容器）：

```
.msg.user       > .bubble
.msg.assistant  > .tool-badges > .badge(.running|.ok|.fail) > .bubble
                > .flow-line > .flow-node(.hit|.flow-intent) > .flow-arrow
                > .source-list > .source-chip
                > .feedback > .feedback-inner > .fb-btn(.active|.locked)
                > .actions > .action-btn(.primary|.done)
.msg.system     > .bubble            (居中系统消息)
.bubble.abstained                    (拒答：虚线/降权气泡)
.cite                                (正文里的引用角标 [1])
.confirm-card[data-state=approve|reject] > .confirm-title/.confirm-desc/.confirm-note/.confirm-actions > .confirm-btn(.primary)
.order-cards > .order-hint / .order-card > .order-top/.order-mid/.order-bottom
.refund-form > .refund-title/label/select/.refund-actions
.conv-item(.active) > .conv-meta / .conv-tag     (左侧会话项)
#source-panel > .source-head / #source-body > .source-where/.source-q/.source-a/.source-meta
```

外框结构参考（可以改骨架，但语义要保留）：顶栏（品牌 + 新会话 + 后台入口）／会话列表／消息区／输入区／来源原文面板。

## 8. 真实内容（逐字使用，不许改写、不许翻译）

**顶栏**：品牌名「小智」；副标题「电商智能客服 · 会查单 · 会引用 · 会拒答」；按钮：「新会话」「飞轮审核」「主题分布」。

**左侧会话列表（4 条，第一条 active）**
1. 订单 1001 怎么还没发货 · 今天 14:22 · 标签「进行中」
2. 退款到账要多久 · 今天 11:40
3. 尺码不合适能换吗 · 昨天 20:15
4. 帮我改一下收货地址 · 昨天 09:03 · 标签「已转人工」

**主对话（从上到下，顺序固定）**

① 用户：「订单 1001 怎么还没发货」

② 助手：
- flow-line：意图：查订单 → 路由：order_tool → 工具：query_order
- 徽章：`query_order · 已完成`（ok 态）
- 气泡文字：「订单 **1001** 是「无线蓝牙降噪耳机」× 1，实付 **¥399.00**，下单时间 2026-08-07，当前状态 **待发货**。仓库一般在付款后 48 小时内出库；今天已经第 3 天，建议直接催发。」
- 来源 chip：「售后处理手册 > 发货时效」
- 反馈行：「这条答案有帮助吗」+ 两个按钮（👍 / 👎，用字符或纯 CSS 图形，不要 emoji 图）

③ 用户：「能帮我催一下吗」

④ 助手：
- 徽章：`create_ticket · 待确认`（running 态）
- 确认卡：标题「提交工单 · 物流催发」；描述「订单 1001 已超 48 小时未出库，申请仓库优先出库并回电告知预计发出时间。」；注「确认后才会提交给人工客服，取消不建单。」；按钮「确认提交」（primary）+「取消」
- 气泡（短）：「提交前需要你确认一下——我不会替你直接建单。」

⑤ 用户：「退款到账要多久」

⑥ 助手（这条是主视觉，最完整）：
- flow-line：意图：售后咨询 → 路由：kb_rag → 检索 5 条 · 命中 2 条 · 置信度 0.72（「置信度 0.72」用等宽数字）
- 气泡文字（引用角标用 `.cite`，标号保持 [1] [2]）：
  「退货退款在仓库**验收通过后 3 个工作日内**发起退款[1]；到账时间看支付渠道，原路退回微信/支付宝一般 1–3 个工作日，银行卡 3–7 个工作日[2]。客服侧只说明发起时效，不承诺具体到账日期。」
- 来源 chips：「售后处理手册 > 工单类型与时效」「售后处理手册 > 退货流程」
- 反馈行 + 「这条答案有帮助吗」

⑦ 用户：「那双十一买的东西也能这样退吗」

⑧ 助手（拒答示例，`.bubble.abstained`）：
- flow-line：意图：售后咨询 → 路由：kb_rag → 检索 5 条 · 命中 0 条 · 置信度 0.31
- 气泡文字：「这一点我查不到确切条款——大促期间的退换规则和日常不同，知识库里还没有这一条。已经记下来交给人工补充，你可以先转人工确认。」
- 按钮：`转人工`（action-btn）

**来源原文面板（打开状态，面板标题「来源原文」）**
- `.source-where`：售后处理手册 > 工单类型与时效
- `.source-q`：问：退货退款多久能到账
- `.source-a`：「退货退款：2 小时内响应；到仓验收通过后 3 个工作日内退款；需要寄回商品；超 3 个工作日未完结自动升级。」
- `.source-meta`：命中相似度 0.72 · 知识块 #2 · vector_id 2

## 9. 视觉母题（form 来自内容的哪里）

内容的本质是**一次可以回放的客服台账**：谁在什么时候说了什么、依据哪一条、动了哪个系统。
所以母题必须落在「**编号 · 时间戳 · 出处 · 状态**」这套台账要素上，而不是通用的 SaaS 卡片堆叠。
每版交付时写一句：form 来自内容的哪里（写不出说明在套模板）。

## 10. 图片

本页**不需要图片**：它是工具/数据型界面，任何 stock 图或生图都是装饰 = slop。
视觉表现力全部由排版、线条、色阶、数字与状态承担。
